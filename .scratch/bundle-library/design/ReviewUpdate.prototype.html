Ticket 05 — how does Review & Update make its narrower rules legible?

Three variants on the window the Library opens when a Reviewer edits a composed Bundle. The Editor behind the scrim is rough on purpose; the modal is at the real geometry (521 × 736 — window height minus 64, that over 1.414), so a design that needs more width has to say so out loud.

Settled, and not up for grabs here: editable are the Bundle title, Bundle notes, Finding notes and Marker notes — nothing else. Images cannot be added, removed, reordered or replaced. Every edit sits in a buffer until Save, and this window never reads or writes a Finding (BR-65: it shows what was composed, not the Findings as they are now).

Type in the fields. They are real, each variant tracks its own dirty set, and the bar at the bottom prints it. Cancel and Save do what that variant says they do. The bar also flips the app's theme, because a rule made legible by colour has to survive both.

Settled 2026-08-31 by the owner: variant C, with one amendment — Save stays clickable at all times, even with nothing changed. A and B are kept below because they are the record of why C was chosen, not live options. Verified in the store before applying: the amendment is free. update_bundle_markdown writes the markdown column and nothing else, a Bundle has no updated_at, and the Library sorts ORDER BY composed_at DESC — so a Save with no changes cannot reorder the Library or alter a single thing a Reviewer can see.

?variant=A Nothing added not taken the compose window with two things taken away, and no lock treatment at all

Disputes the ticket's premise. In compose mode the image blocks carry no affordance either — the Finding set is chosen in the filmstrip, never in this modal (appwindow.slint:2403) — so there is nothing here to take away and nothing to grey out. A lock chip would invent a control in order to disable it. What does change: the live N Findings · ~N tk readout becomes a static provenance line, because a count that cannot move is not a readout; and Edit/Preview stays, because a Reviewer about to hand this over still wants to see the file. Cost: a Reviewer who expected to swap an image learns they cannot only by failing to find how.

Not taken. Its Save behaviour was, though: the owner kept always clickable from here and put it on C.

?variant=B Provenance rail not taken a second column that states the rules in words and names every unsaved change

Says it once, in prose, instead of decorating each image. The rail also carries what the header used to, and adds the thing no other variant has: a live list of what is unsaved, so the discard dialog can name exactly what is about to be lost. Cost, and it is the real one: the rail does not fit. At 521px the document column would be about 300px wide, so this variant is drawn at 760px — which breaks the height / 1.414 width the compose modal is built on (appwindow.slint:3391). Either the two modals stop sharing a geometry, or both get wider and the compose window changes for a reason that has nothing to do with composing.

Not taken — the owner ruled out anything of this shape outright, so the width question it raised never had to be settled. Its dirty-only Save went with it.

?variant=C Read first, unlock to edit chosen opens read-only; the primary button is Edit, and Save is always clickable once unlocked

Changes the primary affordance. The window opens as the Bundle was composed — which is BR-65 made visible rather than merely obeyed — and the Edit/Preview toggle disappears because locked already is the preview: two controls collapse into one. Unlocking flips the header badge to an accent state, and only then do the images get an explicit lock chip, because only then is everything around them editable and the exception needs saying. Cost: every edit costs one extra click, and a Reviewer who came from the Library specifically to fix one typo pays it every time.

Chosen, with Save always clickable. A Save that changed nothing writes the same string into the same column, and since a Bundle carries no updated_at and the Library orders by composed_at, there is nothing for it to disturb. What it buys is a Reviewer who never has to work out why the button is dead. Cancel still confirms only when something has actually been typed — a dialog over an untouched window is a dialog that teaches people to dismiss dialogs.
