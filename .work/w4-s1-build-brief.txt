# Brief for W4-S1: SQLite schema migration v4 (access_key) and AccessKeyStore

## Objective
Implement `access_key` database migration v4, domain model `AccessKey`, repository port `AccessKeyStore`, and SQLite implementation `SqliteAccessKeyStore` in `snapdown-core` and `snapdown-store`.

## Scope & Changes Required
1. **`crates/snapdown-core/src/domain/access_key.rs`**:
   - Create `AccessKey` entity struct (`id: String`, `key_hash: String`, `issued_at: String`, `revoked_at: Option<String>`).
   - Create helper `AccessKey::generate_secret()` generating a 32-byte hex (or high-entropy alphanumeric `sd_key_...`) secret token and computing its SHA-256 hash in hex string format.
   - Implement `AccessKey::verify_secret(&self, secret: &str) -> bool` using constant-time comparison (e.g. `subtle::ConstantTimeEq` or constant-time XOR comparison over byte slices).
   - Export in `crates/snapdown-core/src/domain/mod.rs` and `crates/snapdown-core/src/lib.rs`.

2. **`crates/snapdown-core/src/ports/access_key_store.rs`**:
   - Define trait `AccessKeyStore: Send + Sync`:
     - `fn get_active_key(&self) -> Result<Option<AccessKey>, StoreError>`
     - `fn save_key(&self, key: &AccessKey) -> Result<(), StoreError>`
     - `fn revoke_active_key(&self) -> Result<(), StoreError>`
     - `fn verify_key(&self, secret: &str) -> Result<AuthResult, StoreError>` where `AuthResult` indicates `Valid`, `Invalid`, or `NoKeyConfigured`.
   - Export in `crates/snapdown-core/src/ports/mod.rs`.

3. **`crates/snapdown-store/src/sqlite/migrations.rs`**:
   - Add Migration 4:
     ```sql
     CREATE TABLE IF NOT EXISTS access_key (
         id TEXT PRIMARY KEY,
         key_hash TEXT NOT NULL,
         issued_at TEXT NOT NULL,
         revoked_at TEXT
     );
     ```

4. **`crates/snapdown-store/src/sqlite/access_key_store.rs`**:
   - Implement `SqliteAccessKeyStore` wrapping `rusqlite::Connection` (or `Arc<Mutex<Connection>>` / connection handle).
   - When saving a new key, automatically revoke any previously un-revoked keys within the same transaction (ensuring exactly one active key).
   - Export in `crates/snapdown-store/src/sqlite/mod.rs` and `crates/snapdown-store/src/lib.rs`.

5. **`crates/snapdown-store/tests/test_sqlite_access_keys.rs`**:
   - Write integration tests verifying:
     - Migration v4 applies cleanly and idempotently.
     - Issuing a key stores hash and sets active status.
     - Issuing a second key revokes the first automatically.
     - Revoke explicitly marks active key revoked.
     - Constant-time verification returns `Valid` for correct secret, `Invalid` for wrong/revoked secret, `NoKeyConfigured` when no active key.
