## Intent

**Problem:**
In `apps/web-service/internal/server/server.go:145`, the default HTML wrapper for `GET /b/{slug}` is constructed using `fmt.Sprintf` with unescaped format verbs (`%s`):
```go
html := fmt.Sprintf(`<!DOCTYPE html>
<html>
<head><meta charset="utf-8"><title>Snapdown Review - %s</title></head>
<body><pre>%s</pre></body>
</html>`, slug, b.Markdown)
```
`b.Markdown` is the Reviewer's own Note and finding text, published verbatim. Because `%s` performs no HTML escaping or entity encoding, a Note containing HTML markup or script breakout tags (e.g. `</pre><script>alert(1)</script><pre>`) breaks out of the `<pre>` tag and executes arbitrary JavaScript in the browser of anyone opening the publication URL. The endpoint is completely public and unauthenticated.
Furthermore, `slug` is interpolated directly into `<title>` without escaping. Although slugs are currently 160-bit CSPRNG values generated by the backend, relying on caller behavior creates an unsafe latent seam.

**Boundaries & Non-Goals (under DEC-005 freeze):**
- `DEC-005` freezes `sharing` and permits this work under its own rule: *"This decision does not forbid a fix. It forbids new work."*
- **No widening:** No new routes, no changes to route tables or API contracts, no UX changes, no new use cases, and no reader SPA (rows 11, 14, 15 of `inventory-screen.md` and `LC-027` remain deferred/open per `BUG-2`/`OQ-22`).
- `NFR-15` MUST survive unchanged: `GET /b/{slug}` with an unknown or revoked slug returns the identical 404 response. The service exposes no enumeration or listing route.
- Output encoding only affects the default HTML response when `Accept` does not request raw markdown. `GET /b/{slug}/raw.md` and `GET /b/{slug}` with `Accept: text/markdown` or `Accept: text/plain` continue to serve verbatim raw Markdown bytes without escaping.

**Approach:**
1. In `apps/web-service/internal/server/server.go`:
   - Use `html.EscapeString` (from the standard `html` package) or `html/template` to escape both `b.Markdown` and `slug` when generating the HTML body for `handleGetBundle`.
   - Ensure the raw markdown endpoints (`handleGetRawMarkdown` and `handleGetBundle` with Markdown Accept header) remain untouched and verbatim.
2. In `apps/web-service/internal/server_test.go`:
   - Implement the four required tests from `waves.yaml` and the brief:
     - `a_note_containing_markup_is_escaped_in_the_rendered_page`
     - `a_note_that_closes_the_pre_block_cannot_reach_the_browser_as_markup`
     - `the_slug_is_escaped_in_the_rendered_page`
     - `an_unknown_slug_still_returns_the_identical_refusal`
   - **Assert behavior, not hardcoded escaped literals:** Tests must parse/inspect the HTML response structure or verify that tags (like `<script>`, `</pre>`, `<b>`, `<img>`) do not exist as live DOM/markup elements and that closing `</pre>` tags are escaped as `&lt;/pre&gt;`, rather than duplicating a hardcoded string literal.

## Tasks & Acceptance

**Execution:**
- `apps/web-service/internal/server/server.go` -- Import `html` (or `html/template`) and escape `b.Markdown` and `slug` before rendering the HTML wrapper in `handleGetBundle`.
- `apps/web-service/internal/server_test.go` -- Add test cases covering markup escaping, `<pre>` breakout prevention, slug escaping, and NFR-15 refusal preservation.

**Acceptance Criteria:**
- Given a published bundle whose Note contains `<script>alert('xss')</script>` and `<b>bold</b>`, when fetching `GET /b/{slug}` with default Accept headers, the response status is 200, Content-Type is `text/html; charset=utf-8`, and the body contains escaped text (`&lt;script&gt;` / `&lt;b&gt;`) such that no `<script>` tag is rendered unescaped in HTML.
- Given a published bundle whose Note contains `</pre><script>alert(1)</script><pre>`, when fetching `GET /b/{slug}` as HTML, the `</pre>` tag inside the note is escaped as `&lt;/pre&gt;` so it cannot close the outer `<pre>` container.
- Given a published bundle with a slug containing special characters (e.g. `test<slug>&42`), when fetching `GET /b/{slug}`, the title element contains the escaped slug `Snapdown Review - test&lt;slug&gt;&amp;42`.
- Given `GET /b/{slug}/raw.md` or `GET /b/{slug}` with `Accept: text/markdown`, the server returns verbatim raw Markdown with zero escaping applied.
- Given an unknown or revoked slug, `GET /b/{slug}` returns HTTP 404 with the exact JSON body required by `NFR-15` (`code: not_found`, `message: Publication not found or has been unpublished`).
- All existing tests in `apps/web-service/internal` and `cargo test --workspace` continue to pass cleanly.

## Design Notes

**Escaping Strategy:**
Using `html.EscapeString` on `slug` and `b.Markdown` within `handleGetBundle` (or rendering via `html/template.HTMLEscapeString`) is minimal, robust, standard library based, and zero-allocation overhead for the small wrapper. It guarantees that any HTML meta-characters (`&`, `<`, `>`, `"`, `'`) are converted to their corresponding HTML entities.

**Preservation of Markdown & Raw Routes:**
The raw endpoint `GET /b/{slug}/raw.md` and content-negotiated markdown `GET /b/{slug}` (`Accept: text/markdown`) must return unescaped markdown so that programmatic consumers (such as coding agents) receive pristine markdown.
