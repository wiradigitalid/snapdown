## Containers

Headings here are the `built: true` containers from `.control/registry/components.yaml` whose code
exists. `mcp-bridge` and `web-api` are registered and have **no code yet** — W4 and W5 build them — so
they correctly have no heading, and V25 reports both until then. That pair is the whole of the
validator baseline's V25 section.

### desktop-app

Tauri v2. A Rust process owning the domain core and every adapter, with a React webview for the
Editor and Settings. The only writer in the product.

```text
apps/desktop/
  index.html         ★ the Vite entry document. Mounts #root
  package.json       ★ scripts: dev, build, typecheck, lint, test
  vite.config.ts     ★ build and test configuration
  tsconfig.json      TypeScript configuration
  eslint.config.js   flat config, this directory only
  src/               the React webview
    main.tsx         ★ mounts App into #root
    App.tsx          ★ the shell. One screen today
    styles/
      tokens.css     imports the shared token stylesheet from web/ui
    test/            vitest suites and setup
  src-tauri/         the Rust half
    Cargo.toml       ★ crate manifest. Declares the lib and the binary
    build.rs         tauri-build
    src/
      main.rs        ★ composition root: tray, single-instance, window
      lib.rs         library entry point
    tauri.conf.json  ★ window, tray, bundle, and security configuration
    capabilities/    Tauri permission sets
    icons/           application and tray icons
    gen/             generated by tauri-build. Ignored
  dist/              generated by Vite. Ignored
```

**Flow:** `apps/desktop/src/main.tsx` → `apps/desktop/src/App.tsx` → components imported
from `web/ui`. On the Rust side
`src-tauri/src/main.rs` is the composition root; it wires the tray and the window, and it is where
adapters from `crates/` get constructed. Nothing in `src/` reaches a crate directly — it goes through
Tauri commands registered in `main.rs`.

### web-ui

React + Vite. The shared component library today; from W5 it is also the published-Bundle reader that
runs in a reader's browser. Both front ends import from here, which is what makes one design system
possible rather than two.

```text
web/ui/
  package.json       ★ scripts: typecheck, lint, test. Consumed as @snapdown/ui
  tsconfig.json      TypeScript configuration
  eslint.config.js   flat config, this directory only
  vitest.config.ts   test configuration
  src/
    index.ts         ★ the public surface. A component not exported here does not exist to a consumer
    components/      one file per base element, per .how/_platform/design-system.md
    styles/
      tokens.css     ★ every token's value, in both colour schemes. The single source
      components.css ★ every interactive state — focus-visible, hover, active, invalid, disabled
    test/            vitest suites and setup
```

**Flow:** a consumer imports from `web/ui/src/index.ts` only. `components.css` carries the state matrix
because inline styles cannot express `:hover`, `:active`, or `:focus-visible` at all — that is a rule,
not a preference, and `design-system.md` § Rules that bind every screen is why.

## Libraries

### `crates/snapdown-core`

The domain. Consumed by `snapdown-store` and by `apps/desktop/src-tauri`.

```text
crates/snapdown-core/
  Cargo.toml         ★ its dependency list IS the constraint. Nothing here may reach I/O
  src/
    lib.rs           ★ the public surface
    domain/          entities and their invariants
    ports/           ★ the traits the core calls out through: Clock, SettingsStore, BlobStore,
                     HotkeyRegistrar, StartupRegistrar
    util/            id construction. Takes time as a parameter; it never reads a clock
  tests/
    test_no_io.rs    ★ walks the resolved dependency graph and fails on any I/O, clock, or entropy
                     crate. This test is the enforcement of the whole paradigm
```

### `crates/snapdown-store`

The adapters: SQLite and the Vault filesystem. Consumed by `apps/desktop/src-tauri`. A skeleton
today — W1-S2 fills it.

```text
crates/snapdown-store/
  Cargo.toml
  src/
    lib.rs           the crate surface
```
