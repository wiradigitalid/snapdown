## Containers

Headings here are the `built: true` containers from `.control/registry/components.yaml` whose code
exists. `mcp-bridge` and `web-api` are registered and have **no code yet** — W4 and W5 build them — so
they correctly have no heading, and V25 reports both until then. That pair is the whole of the
validator baseline's V25 section.

### desktop-app

Tauri v2. A Rust process owning the domain core, settings store, and every adapter, with a React webview for the
Editor and Settings (Screen 12). The only writer in the product.

```text
apps/desktop/
  index.html         ★ the Vite entry document. Mounts #root
  package.json       ★ scripts: dev, build, typecheck, lint, test
  vite.config.ts     ★ build and test configuration
  tsconfig.json      TypeScript configuration
  eslint.config.js   flat config, this directory only
  src/               the React webview
    main.tsx         ★ mounts App into #root
    App.tsx          ★ the Settings screen (Screen 12)
    components/      GeneralSection, VaultSection, QualityBudgetSection, HotkeySection
    services/        settings Tauri IPC client bridge
    types/           TypeScript settings DTO definitions
    styles/
      tokens.css     imports the shared token stylesheet from web/ui
    test/            vitest suites and shell tests
  src-tauri/         the Rust half
    Cargo.toml       ★ crate manifest. Declares the lib and the binary
    build.rs         tauri-build
    src/
      main.rs        ★ composition root: tray, single-instance, window launch
      lib.rs         library entry point, plugin registrations, IPC handlers
      state.rs       AppState DI container (SqliteSettingsStore, HotkeyRegistrar, StartupRegistrar)
      commands/      Tauri IPC commands: settings, hotkey, startup
      hotkey/        DesktopHotkeyRegistrar with tauri-plugin-global-shortcut backend
      startup/       DesktopStartupRegistrar with Windows HKCU autostart registry backend
      vault_migration.rs atomic vault file migration runner with rollback
    tauri.conf.json  ★ window, tray, bundle, and security configuration

    icons/           application and tray icons
    gen/             generated by tauri-build. Ignored
  dist/              generated by Vite. Ignored
```

### web-ui

React + Vite. The shared component library today; from W5 it is also the published-Bundle reader that
runs in a reader's browser. Both front ends import from here, which is what makes one design system
possible rather than two.

```text
web/ui/
  package.json       ★ scripts: typecheck, lint, test. Consumed as @snapdown/ui
  tsconfig.json      TypeScript configuration
  eslint.config.js   flat config, this directory only
  vitest.config.ts   test configuration
  src/
    index.ts         ★ the public surface. A component not exported here does not exist to a consumer
    components/      Button, TextField, TextArea, Modal, Toast, ConfirmDialog, Checkbox, Markdown, EmptyState
    styles/
      tokens.css     ★ every token's value, in both colour schemes. The single source
      components.css ★ every interactive state — focus-visible, hover, active, invalid, disabled
    test/            vitest suites and setup
```

### mcp-bridge

The stdio Model Context Protocol executable an agent's MCP client launches. It holds no Library state,
persists neither the Access Key nor any content between runs, and reaches the Library only through the
Local API — which AD-5 makes read-only. That is why it is a separate binary while the Editor is not
(`DEC-002` for the reason it exists; AD-11 for why it is not an exception to one-process).

```text
crates/snapdown-bridge/
  Cargo.toml         ★ produces snapdown-bridge.exe
  src/
    main.rs          ★ the stdio MCP loop. Four tools: set_access_key, list_bundles,
                     ★ read_bundle, read_bundle_image
```

### web-api

The Go service that serves published Bundles. A single binary with embedded SQLite and a blob
directory, on a host the Reviewer controls. It shares no code with the Rust tree and depends on
nothing in it except the Markdown and image bytes a publish hands it.

Frozen by `DEC-005` for the duration of the desktop experience work: it keeps running, and it receives
no new work.

```text
apps/web-service/
  go.mod             ★ module definition
  main.go            ★ entry point and flag parsing
  internal/
    server/
      server.go      ★ chi routes: publish, unpublish, reconcile, and the public read routes
    store/
      store.go       ★ embedded SQLite plus the blob directory
    server_test.go   route inventory and the NFR-15 identical-refusal test
```

## Libraries

### `crates/snapdown-core`

The domain. Consumed by `snapdown-store` and by `apps/desktop/src-tauri`.

```text
crates/snapdown-core/
  Cargo.toml         ★ its dependency list IS the constraint. Nothing here may reach I/O
  clippy.toml        ★ disallowed-methods deny configuration for std::fs, std::env, std::time
  src/
    lib.rs           ★ the public surface
    domain/          entities and their invariants: Setting, SettingKey, SettingValue, QualityBudget, HotkeyAction
    ports/           ★ the traits the core calls out through: Clock, EntropySource, SettingsStore, BlobStore,
                     HotkeyRegistrar, StartupRegistrar
    util/            id construction (id_from_parts). Pure byte formatting
    error.rs         CoreError definitions
  tests/
    test_no_io.rs    ★ walks the resolved dependency graph and fails on any I/O, clock, or entropy crate
```

### `crates/snapdown-store`

The adapters: SQLite and the Vault filesystem. Consumed by `apps/desktop/src-tauri`.

```text
crates/snapdown-store/
  Cargo.toml         SQLite (rusqlite) and filesystem dependencies
  src/
    lib.rs           the crate surface exports
    error.rs         StoreError mapping to CoreError
    system.rs        SystemClock (RFC3339 UTC 'Z') and SystemEntropySource adapters
    sqlite/
      mod.rs         SQLite store module
      migrations.rs  forward-only idempotent schema migrations (setting, schema_version)
      settings_store.rs SqliteSettingsStore with WAL mode, integrity check, and default fallback
    vault/
      mod.rs         VaultBlobStore with canonical root confinement and path traversal refusal
  tests/
    test_sqlite_settings.rs SQLite integration tests
    test_vault_blob.rs      Vault filesystem confinement and traversal attack integration tests
```
