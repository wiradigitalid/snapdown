## Containers

Headings here are the `built: true` containers from `.control/registry/components.yaml` whose code
exists. `web-api` is registered and has **no code yet** — W5 builds it — so it correctly has no
heading, and V25 reports it until then. `mcp-bridge` stood in this list too, until `DEC-016` withdrew
the container on 2026-09-04; `crates/snapdown-bridge` is removed by the separate dispatch that
decision unblocked.

### desktop-app

Native Slint (DEC-007), replacing Tauri v2 + React. One Rust process, one binary (`Snapdown.exe`,
crate `snapdown-desktop`), owning the domain core, every store adapter, the tray, global hotkeys,
autostart, the capture overlay, and the Editor window — AD-11's one-process rule, unchanged by the
framework move. The only writer in the product. At this Verified date it renders two screens
(Editor shell, Capture Overlay with its note field); everything else the corpus promises for this
container — Findings management beyond the filmstrip, Bundles, Settings, and the Orphan
report — has no Slint implementation yet (`DEC-007` Cost, `inventory-screen.md` findings). Agent
access and the Local API stood in that list too until `DEC-016` withdrew both on 2026-09-04.

```text

  build.rs           slint-build codegen + embed-resource (Windows icon/manifest)
  app.manifest       Windows application manifest, embedded by build.rs
  app.rc             Windows resource script: exe icon

A `### mcp-bridge` container heading stood here — the stdio Model Context Protocol executable an
agent's MCP client launched, `crates/snapdown-bridge` — until 2026-09-04. `DEC-016` withdrew the
running channel it fronted; the crate is removed by the separate dispatch that decision unblocked.

### web-api

The Go service that serves published Bundles. A single binary with embedded SQLite and a blob
directory, on a host the Reviewer controls. It shares no code with the Rust tree and depends on
nothing in it except the Markdown and image bytes a publish hands it.

Frozen by `DEC-005` for the duration of the desktop experience work: it keeps running, and it receives
no new work.

```

## Libraries

### `crates/snapdown-core`

The domain. Consumed by `snapdown-store` and by `apps/desktop/src-tauri`.

```text
crates/snapdown-core/
  Cargo.toml         ★ its dependency list IS the constraint. Nothing here may reach I/O
  clippy.toml        ★ disallowed-methods deny configuration for std::fs, std::env, std::time
  src/
    lib.rs           ★ the public surface
    domain/          entities and their invariants: Setting, SettingKey, SettingValue, QualityBudget, HotkeyAction
    ports/           ★ the traits the core calls out through: Clock, EntropySource, SettingsStore, BlobStore,
                     HotkeyRegistrar, StartupRegistrar
    util/            id construction (id_from_parts). Pure byte formatting
    error.rs         CoreError definitions
  tests/
    test_no_io.rs    ★ walks the resolved dependency graph and fails on any I/O, clock, or entropy crate
```

### `crates/snapdown-store`

The adapters: SQLite and the Vault filesystem. Consumed by `apps/desktop/src-tauri`.

```text
crates/snapdown-store/
  Cargo.toml         SQLite (rusqlite) and filesystem dependencies
  src/
    lib.rs           the crate surface exports
    error.rs         StoreError mapping to CoreError
    system.rs        SystemClock (RFC3339 UTC 'Z') and SystemEntropySource adapters
    sqlite/
      mod.rs         SQLite store module
      migrations.rs  forward-only idempotent schema migrations (setting, schema_version)
      settings_store.rs SqliteSettingsStore with WAL mode, integrity check, and default fallback
    vault/
      mod.rs         VaultBlobStore with canonical root confinement and path traversal refusal
  tests/
    test_sqlite_settings.rs SQLite integration tests
    test_vault_blob.rs      Vault filesystem confinement and traversal attack integration tests
```
